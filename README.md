# МЕДИА.СТРАЖ

Веб-сайт в корне репозитория — демонстрация рейтинга. Рабочий прототип в
`media_strazh/` собирает публикации RT, ТАСС и РИА Новости из общих RSS-лент,
извлекает основной текст, запускает анализ и сохраняет результаты в SQLite.
Он также принимает текст вручную и выдаёт точные цитаты и вопросы для проверки.
Рейтинг СМИ, вероятность манипуляции и фактчекинг пока не реализованы.
Качество распознавания на размеченных реальных публикациях ещё не измерено.

## Автоматический сбор

На Linux с Python 3.10+ из корня репозитория:

```sh
python3 -m media_strazh collect --limit 5 --verbose
python3 -m media_strazh watch --interval 300 --limit 5
```

`collect` выполняет один цикл. `watch` постоянно проверяет общие ленты всех трёх
источников с паузой 300 секунд после каждого цикла. Новые публикации анализируются
без ручного ввода. База по умолчанию — `data/media-strazh.sqlite3`; она переживает
перезапуск процесса. Один сборщик на базу; одновременно с `watch` запускать
`collect`/`reextract`/`reanalyze` не нужно. Состояние можно читать в любое время:

```sh
python3 -m media_strazh status
python3 -m media_strazh export-corpus --output exports/pilot.jsonl
```

После обновления правил остановите свой сборщик, выполните
`python3 -m media_strazh reanalyze` и запустите `watch` снова. Пересчёт сохраняет
результаты новой версии для уже полученных текстов без загрузки сайтов; предыдущие
результаты, даты получения и расписание сохраняются. После обновления извлечения
используйте `reextract`, который также запускает текущий анализ на исправленном тексте.

В текущей среде на реальных страницах проверены RT и РИА. Для ТАСС доступна RSS,
но страницы статей и `robots.txt` отвечают HTTP 403; ссылки сохраняются, получение
основного текста остаётся заблокированным. Обычная лента не гарантирует полноту
охвата всех публикаций СМИ. Сбор и ограничения описаны в
[docs/collection.md](docs/collection.md).

## Запуск

Нужен Python 3.10+; внешних зависимостей и ключей API нет. Из корня репозитория:

```sh
python3 -m media_strazh serve --port 8001
```

Сервер запускает форму анализа на пути `/`, список собранных публикаций на
`/articles`, API `POST /api/v1/analyze`, справочник `GET /api/v1/taxonomy` и
проверку работоспособности `GET /health`. Для чтения базы предусмотрены
`GET /api/v1/articles`, `GET /api/v1/articles/{id}` и
`GET /api/v1/collection/status`. На сервер и сборщик передавайте один и тот же
`--db`, если меняете путь по умолчанию. Сервер слушает `127.0.0.1`; это интерфейс
для разработки без авторизации. Сам сервер не запускает сборщик. Разбор вручную
не сохраняется в базу; результаты автоматического сбора сохраняются.

CLI принимает полный текст статьи из UTF-8 файла или стандартного ввода:

```sh
python3 -m media_strazh analyze --title 'Заголовок публикации' --file /tmp/article.txt
```

Запрос к API:

```sh
curl --fail-with-body -H 'Content-Type: application/json' \
  --data '{"title":"Заголовок","text":"Полный текст статьи."}' \
  http://127.0.0.1:8001/api/v1/analyze
```

Текст обязателен; `title`, `source`, `url`, `published_at` — необязательные строки.
URL сохраняется как метаданные; анализатор не загружает статью по ссылке.
Общий лимит строковых полей — 200 000 Unicode-символов.
Вывод ограничен 500 совпадениями; `summary.findings_truncated` сообщает о неполном
результате. Контекст вокруг фрагмента ограничен 200 символами с каждой стороны;
`sentence.truncated` указывает, что показана только часть длинного предложения.

## Что работает

- Версия `rules-0.2.1`: 26 правил для девяти типов — запугивание, эмоциональная
  оценка, образ врага, преувеличение, обобщение, размытый источник, упрощение,
  кликбейт и дисфемизмы. Фразы и требования к контексту перечислены в
  [docs/rules.md](docs/rules.md); каталог находится в `media_strazh/rules.py`.
- Фрагменты оригинального текста, предложения с контекстом, версия правил и SHA-256
  пары заголовок/текст. Оригинал не нормализуется, чтобы сохранить координаты.
- Статусы `needs_review`, `quoted_candidate`, `context_only`. Сводка кандидатов
  включает только первый статус; `quoted_candidate` также включает переданную речь.
  Кавычки и глагол сообщения сами по себе не устанавливают говорящего.
- В сводке отдельно считаются метки приёмов и уникальные фрагменты для проверки:
  у одного фрагмента могут быть две категории. Медицинский контекст, сообщения
  о животных и произведениях ограничивают применение переносных формулировок.
- Форма для ввода текста, выделение найденных фрагментов и выгрузка результата JSON.
- Оценка по категориям на полностью размеченном JSONL-корпусе.

Координаты `start`/`end` относятся к указанному полю `title` или `text`,
начинаются с нуля, конец не включён. Единица — Unicode code point; в JavaScript
для таких координат используйте `Array.from(text)`, а не обычный `text.slice()`.

Правила выявляют **кандидатов**, а не доказанные манипуляции. По одному слову нельзя
установить намерение автора или достоверность новости. Три остальных типа методики
возвращаются с `coverage: not_evaluated`. Неподдерживаемая категория не считается
отсутствующей. У каждого найденного типа ограниченный набор формулировок;
семантически похожие выражения могут быть пропущены.

## Проверка и измерение качества

```sh
python3 -m unittest discover -s tests -v
python3 -m media_strazh evaluate --file /tmp/annotated.jsonl
```

Тесты проверяют поведение программы на специально написанных примерах и коротких
фрагментах статьи, выбранной пользователем. Эти примеры использовались при разработке
и не являются независимой оценкой точности. Для оценки нужен отдельный корпус.
Формат, правила разметки и этапы разработки описаны в
[docs/algorithm.md](docs/algorithm.md).
