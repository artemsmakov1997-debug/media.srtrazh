# Просмотр в GitHub и перенос в основную ветку

Код анализатора подготовлен в рабочем каталоге Codex
`/workspace/media.srtrazh`, в локальной ветке `feature/media-analysis`.
Наличие локальной ветки не означает, что она отправлена в GitHub: это нужно
проверить на странице репозитория. Облачная среда Codex и GitHub Codespaces — разные среды.
Открытие нового Codespace основной ветки сейчас даст исходный демонстрационный
проект без нашего анализатора.

Репозиторий: https://github.com/artemsmakov1997-debug/media.srtrazh.

## 1. Проверить подготовленный код

В текущей среде из корня репозитория можно проверить ветку и последний коммит:

```sh
git status --short --branch
git log -1 --oneline
python3 -m unittest discover -s tests -q
```

Подготовленные файлы:

- `.gitignore` — исключения для базы, корпуса и временных файлов;
- `README.md` — запуск и возможности;
- `media_strazh/` — анализатор, сборщик, API и интерфейс;
- `tests/` — проверки;
- `docs/` — методика, правила, сбор и эта инструкция.

Демонстрационные HTML-страницы и изображения уже находятся в репозитории.
База `data/`, скачанные статьи и отчёты `exports/` исключены из Git.
В новой среде нужно выполнить сбор, чтобы в интерфейсе появился корпус.

## 2. Отправить отдельную ветку в GitHub

Для отправки необходимы учётные данные с правом записи в репозиторий.
Установка GitHub App и успешное чтение публичного репозитория сами по себе
не подтверждают право записи текущей облачной сессии.

При доступном GitHub CLI безопасные проверки показывают только имя аккаунта
и права на репозиторий:

```sh
gh api user --jq .login
gh api repos/artemsmakov1997-debug/media.srtrazh --jq .permissions
```

Если `push` равен `false`, отправка заблокирована. Нужно исправить подключение
GitHub в Codex/ChatGPT. При расхождении аккаунта в настройках и ответа API
следует обратиться в поддержку с этими результатами; выдавать доступ
неизвестному аккаунту не нужно. Значения токенов не отправлять в чат.

Когда доступ подтверждён, из подготовленной локальной ветки выполнить:

```sh
git push -u origin feature/media-analysis
```

После успешной отправки открыть репозиторий и выбрать `feature/media-analysis`
в списке веток. Это не изменяет `main`.

### Альтернатива: загрузка файлов через браузер

Этот способ подходит только если исходные файлы уже удалось сохранить
на свой компьютер. Ссылка на локальный ZIP в чате может не поддерживаться
интерфейсом: ошибка скачивания не означает, что архив повреждён.

1. Войти в GitHub и открыть репозиторий.
2. На вкладке **Code** открыть список веток, где выбрана `main`.
3. Ввести `feature/media-analysis` и выбрать создание этой ветки из `main`.
   Если имя уже занято, выбрать другое, например `feature/media-analysis-v2`.
4. Убедиться, что выбрана новая ветка. Выбрать **Add file → Upload files**.
5. Перетащить подготовленные `media_strazh`, `tests`, `docs`, `README.md` и
   `.gitignore`. Сам ZIP загружать не нужно: GitHub не распаковывает его в код.
6. Проверить структуру: например, файл должен попасть в
   `media_strazh/analysis.py`, а не в дополнительный каталог с именем архива.
   `.gitignore` может быть скрыт файловым менеджером; включить показ скрытых
   файлов и убедиться, что он попал в список загрузки.
7. В поле сообщения коммита написать `Add automatic media collection and rhetoric analysis`.
8. Сохранить изменения в выбранной новой ветке кнопкой **Commit changes**.

После этого код уже находится в облаке GitHub и его можно читать в браузере.
Для обзора начать с `README.md`, `docs/rules.md`, `media_strazh/rules.py` и
`media_strazh/analysis.py`.

## 3. Проверить работу в GitHub Codespaces

1. На странице репозитория выбрать ветку с загруженным кодом.
2. Открыть **Code → Codespaces → Create codespace on …** для этой ветки.
   Доступность Codespaces и время использования зависят от лимитов аккаунта.
3. В открывшемся редакторе открыть терминал. Команды выполнять из корня
   репозитория, где находится `README.md`.
4. Проверить Python: `python3 --version`. Нужна версия 3.10 или новее;
   внешних Python-зависимостей и ключей API у прототипа нет.
5. Выполнить проверки:

   ```sh
   python3 -m unittest discover -s tests -v
   ```

   Для подготовленного кода ожидаются 101 проверка и итог `OK`.

6. Получить несколько реальных статей:

   ```sh
   python3 -m media_strazh collect --source rt --source ria --limit 3
   ```

   Проверить результат команды и ошибки источников. Возможность доступа из
   Codespaces может отличаться от доступа в текущей среде Codex. Здесь ТАСС
   разрешает RSS, но полный текст заблокирован HTTP 403.

7. Запустить интерфейс:

   ```sh
   python3 -m media_strazh serve --port 8001
   ```

   Этот терминал будет занят сервером. Открыть панель **Ports**. Если порт
   `8001` не появился автоматически, добавить его через **Forward a Port**.
   Оставить видимость порта **Private** и нажать **Open in Browser**.
   Использовать предоставленный Codespaces адрес.

8. На открывшейся странице доступна форма анализа. Перейти на путь `/articles`
   по тому же адресу, чтобы увидеть полученные публикации. Открытие статьи
   показывает текст, найденные фрагменты и объяснения. Нулевое число находок
   означает отсутствие совпадений текущих правил, а не доказанную нейтральность.

9. При необходимости открыть второй терминал и запустить автоматический сбор:

   ```sh
   python3 -m media_strazh watch --interval 300 --limit 5
   ```

   Команда проверяет все три выбранных источника и сохраняет новые статьи с
   анализом. Ошибка ТАСС не останавливает RT и РИА. На одну базу запускать один
   сборщик; не запускать одновременно `collect`, `reextract` или `reanalyze`.
   В другом терминале состояние можно посмотреть командой:

   ```sh
   python3 -m media_strazh status
   ```

Для остановки своего сервера или сборщика использовать `Ctrl+C` в его терминале.
Остановленный Codespace не продолжает сбор. Codespaces подходит для просмотра
и разработки, но не заменяет постоянно работающий сервер.

## 4. Объединить с main

1. В GitHub открыть **Pull requests → New pull request**.
2. Выбрать **base: main**, **compare: feature/media-analysis**
   (или выбранное ранее имя своей ветки).
3. Открыть **Files changed**. Проверить, что добавлены код, тесты и документы;
   базы `data/` и корпуса `exports/` там быть не должно.
4. Создать Pull Request. Подходящее название:
   `Add automatic news collection and expanded rhetoric analysis`.
5. В описание добавить:
   «Сбор RT/ТАСС/РИА через RSS, сохранение полных текстов и результатов в SQLite,
   интерфейс просмотра и 26 правил для девяти категорий. Локально прошли 101
   тест; доступ к полным текстам ТАСС в исходной среде ограничен HTTP 403.
   Качество распознавания на независимом размеченном корпусе ещё не измерено».
   После своей проверки Codespaces добавить её результат.
6. Когда изменения проверены, нажать **Merge pull request → Confirm merge**
   либо выбрать **Squash and merge** и подтвердить. Если GitHub сообщает о
   конфликтах или обязательных проверках, сначала завершить их.
7. Открыть вкладку **Code**, выбрать `main` и убедиться, что там есть
   `media_strazh/`, `tests/`, `docs/` и `README.md`.

После объединения код находится в основной ветке. Для новой среды запускать
его из `main`; существующий Codespace своей ветки автоматически на `main` не
переключается. Создание нового Codespace из `main` — простой способ проверить
результат объединения.

## Что потребуется для публичного сайта и работы 24/7

GitHub хранит исходный код; GitHub Pages обслуживает статические страницы и
не запускает этот Python-сборщик/API. Слияние в `main` само по себе не подключает
результаты анализа к демонстрационному рейтингу сайта.
Для публичной работы нужен отдельный постоянный сервер, хранение базы,
автоматический перезапуск сборщика, защита API и подключение интерфейса к
реальным результатам. Это отдельный этап развёртывания.
