# Автоматический сбор RT, ТАСС и РИА Новости

## Источники и текущая проверка

| Источник | Общая RSS-лента | Результат в текущей среде |
| --- | --- | --- |
| RT на русском | `https://russian.rt.com/rss` | Лента, полный текст и анализ реальных публикаций проверены |
| ТАСС | `https://tass.ru/rss/v2.xml` | Лента HTTP 200; `robots.txt`, главная и проверенная страница статьи HTTP 403 |
| РИА Новости | `https://ria.ru/export/rss2/archive/index.xml` | Лента, полный текст и анализ реальных публикаций проверены |

Тематических фильтров нет. Обрабатываются публикации, найденные в текущих общих
лентах. Это не выгрузка полного исторического архива и не гарантия охвата всех
новостей сайта. Пропускная способность зависит от `--limit`, скорости загрузки
и интервала. Следить за очередью `pending`, особенно при интенсивном потоке.

## Конвейер

1. Загрузить RSS/Atom, проверить структуру и отобрать ссылки на выбранный домен.
2. Нормализовать HTTPS-ссылки, удалить известные метки отслеживания и сохранить
   очередь в SQLite. Короткую аннотацию RSS не использовать как основной текст.
3. Получить страницу, извлечь `NewsArticle.articleBody`, если он есть и относится
   к этой статье, либо использовать адаптер основного HTML-блока издателя.
4. Проверить наличие содержательного русскоязычного текста. Сохранить текст,
   заголовок, канонический URL, даты, версию извлечения и сжатый исходный HTML.
5. Выполнить `analyze`, сохранить результат с версией алгоритма и точными координатами.

На RT вводный абзац `.article__summary` расположен отдельно от `.article__text`;
он включается в текст, когда основная статья найдена. У РИА одноимённый блок
содержит дополнительный пересказ от ИИ и не включается в авторский текст.
Навигация, скрипты, блоки рекомендаций и рекламы исключаются по структуре,
включая RT `.article__read-more`. Дата публикации может извлекаться из относящихся
к странице JSON-LD метаданных, даже когда основной текст находится только в HTML.
Проверка минимального объёма помогает отсеять заглушки, но не доказывает полноту:
при изменениях верстки нужна ручная сверка с оригиналом.

## Повторы, версии и сбои

- Одна статья определяется нормализованной ссылкой. Повторная ссылка не создаёт
  вторую статью. Поля заголовка/текста и метаданные версии проверяются по хешу;
  тот же результат не создаёт повторный анализ для той же версии алгоритма.
- Изменение текста создаёт новую неизменяемую версию. Старые версии и исходные
  страницы сохраняются. При совпадении текста у разных СМИ публикации сохраняются
  отдельно; кластеры перепечаток ещё предстоит выделить для оценки качества.
- Новые и ещё не полученные материалы имеют приоритет. Успешно полученные статьи,
  замеченные в ленте за последние сутки, допускаются к перепроверке через час.
  Это минимальный срок, а не обещание точного времени повторной загрузки.
- Ошибка одной статьи или одного источника не останавливает остальные источники.
  Повторная попытка откладывается на 5 минут с увеличением до часа; HTTP
  `Retry-After` может увеличить паузу. Очередь, ошибки и сроки сохраняются в базе.
- Неудачное обновление не удаляет предыдущий успешно полученный текст и результат.
- Проверка `robots.txt` обязательна для страниц статей. Известный запрет соблюдается.
  Если сам `robots.txt` отвечает 403, допускается только чтение отдельно доступной
  публичной RSS для обнаружения ссылок; загрузки статей остаются остановленными.
- HTTPS и проверка сертификатов сохраняются. Перенаправление на другой домен
  отклоняется, исполнение JavaScript страниц не используется. По умолчанию между
  запросами к одному источнику выдерживается минимум 2 секунды; также учитываются
  `Crawl-delay` и `Request-rate`.

Для ТАСС пока подтверждено ограничение доступа к страницам из этой среды.
Нужен разрешённый издателем способ получения полных материалов или подтверждённый
доступ с будущего сервера. Добавление домена в сетевой список среды уже позволило
читать RSS и не устраняет ответ 403 от страницы. Значения токенов в чат не нужны.

## Команды

Из `/workspace/media.srtrazh`, на Linux с Python 3.10+, внешних пакетов нет:

```sh
python3 -m media_strazh collect --limit 5 --verbose
python3 -m media_strazh status
python3 -m media_strazh watch --interval 300 --limit 5
```

`collect` возвращает код 0 при успешной обработке выбранных источников, 1 при
ошибке или отложенной попытке одного из них, 2 при ошибке параметров/базы.
Успехи остальных источников уже сохранены. `watch` выдаёт события JSON в stdout,
повторяет циклы и сохраняет состояние. SIGINT/SIGTERM завершает процесс после
текущей операции/цикла; HTTP-запрос ограничен таймаутом.

Можно выбрать отдельные источники или сменить RSS на том же домене:

```sh
python3 -m media_strazh collect --source rt --source ria --limit 10
python3 -m media_strazh collect --source ria --feed ria=https://ria.ru/export/rss2/archive/index.xml
```

После реального исправления доступа/настроек можно повторить ошибочные запросы
раньше сохранённого срока: `python3 -m media_strazh collect --retry-now`.
Не использовать этот флаг в расписании: он снимает защиту от частых повторов.

Новые версии извлечения можно проверить на уже сохранённых страницах:

```sh
python3 -m media_strazh reextract
```

Повторное извлечение не запрашивает сайт, не меняет время исходной загрузки и
срок её повторения. Обновлённый текст и результат сохраняются новой версией,
если содержимое изменилось. В текущей среде этим способом исправлены ранее
полученные тексты RT, в которых первоначально отсутствовал вводный абзац.

Не запускать два сборщика или `reextract` одновременно с `watch` для одной базы.
Файловая блокировка предотвращает параллельную запись двух сборщиков.
API и команда `status` могут читать базу одновременно со сбором через SQLite WAL.

## Просмотр и экспорт

```sh
python3 -m media_strazh serve --port 8001
python3 -m media_strazh export-corpus --output exports/pilot.jsonl
```

Интерфейс `/articles` показывает сохранённые публикации, состояние источников
и ошибки. Переход к статье открывает **сохранённый автоматический анализ** с
исходным текстом и фрагментами. `/api/v1/collection/status` показывает последнюю
попытку, успех загрузки ленты и ошибку обработки; живой процесс и открытый порт
сами по себе не доказывают успешного сбора.

Для всех команд доступен `--db /путь/к/базе.sqlite3`. Сервер и сборщик должны
использовать одну базу. Процесс сервера сам по себе не запускает `watch`.
При занятом порте сначала проверить существующий сервис, затем выбрать свободный.

В JSONL-экспорте `fully_annotated=false`, `labels=null`: результаты программы не
подменяют ручные эталонные метки. Перед оценкой категории необходимо разметить
по [инструкции](algorithm.md). Экспорт создаёт новый файл и отказывается
перезаписывать существующий. База, HTML и экспорты находятся в игнорируемых
`data/` и `exports/`; они не добавляются в Git автоматически.

## Проверки и работа 24/7

После изменения версии правил остановить свой `watch`, выполнить
`python3 -m media_strazh reanalyze` и запустить сборщик снова. Пересчёт работает
с сохранёнными текстами без сетевых запросов; предыдущие результаты, тексты,
даты получения и очередь сохраняются. Повторный пересчёт той же версии пропускает
уже обработанные тексты. Допустим фильтр `--source rt` (или `ria`, `tass`).
После исправлений извлечения использовать `reextract` для повторного разбора HTML.

```sh
python3 -m unittest discover -s tests -v
```

Тесты используют синтетические страницы во временных базах и короткие фрагменты
выбранной пользователем статьи: проверяют извлечение,
очередь, версии, отрицательные сценарии, повторные циклы, перезапуск и HTTP API.
Отдельно в текущей среде выполнен сбор реальных RT/РИА и проверены ответы ТАСС.
Это проверка конвейера, а не измерение точности распознавания манипуляций.

Для круглосуточного запуска нужен постоянный Linux-сервер: закрепить рабочую
директорию и Python, запускать один `watch` под диспетчером процессов с перезапуском,
сохранять SQLite и логи на постоянном диске, контролировать ошибки и рост очереди,
настроить резервное копирование базы. Интерфейс разработки предназначен для локального
использования; публичный интерфейс и его авторизация потребуют отдельного развёртывания.
Внешнее развёртывание в этом этапе не выполнено. Процессы облачной среды разработки
не являются гарантией работы 24/7 и не сохраняются в её файловом снимке.
