# Расширение поиска и проверка цитат

Версия `rules-0.4.0` использует общий Python-каталог для автоматического сбора,
API, CLI и ручной формы в браузере. Дизайн страниц при этом не меняется.
Постоянное расширение означает последовательные проверенные версии каталога;
сбор по расписанию сам по себе не придумывает новые правила.

## Что показывает пример пользователя

Публичный пост [«Известий», 253503](https://t.me/izvestia/253503),
опубликованный 9 октября 2026 года, получен через официальный публичный
предпросмотр Telegram 12 октября 2026 года. Сборщик сохраняет тело сообщения,
кавычки/границы HTML-цитат и знак `<...>`. Версия `0.3.2` возвращала 0 находок.
Версия `0.4.0` на том же извлечённом тексте возвращает 11 риторических
фрагментов и отдельное уведомление о пропуске:

| Фрагмент | Что предлагается проверить |
| --- | --- |
| «самая большая угроза безопасности в будущем» | Предельная оценка угрозы, её основания и масштаб |
| «всё станет очевидно»; «очевидно, что» | Объявление вывода очевидным до проверки доводов |
| «как это было на Балканах в 1990-е» | Перенос исторического сценария и различия условий |
| «головорезов» | Уничижительный ярлык и границы обозначаемой группы |
| «может привести к распространению мафиозных структур» | Причинная цепочка пугающего прогноза |
| «неолиберальную военную машину» | Представление сообщества как единой угрожающей силы |
| «всё разваливается» | Обобщённая картина полного разрушения |
| «на грани революции» | Основания прогноза близкого кризиса |
| «правит как диктатор» | Критерии характеристики власти и чья это оценка |
| «если бы … состоялись выборы, … бы их проиграл» | Неопределённость результата несостоявшихся выборов |
| `<...>` | Что удалено из цитаты; самостоятельного вывода об искажении нет |

Все 11 риторических фрагментов имеют `quoted_candidate`: они находятся
в кавычках или явно переданной речи. Это не означает, что редакция безусловно
одобряет высказывания, и не исключает манипулятивного выбора цитат.
`candidate_fragments=11` используется в карточке и фильтре, поэтому признаки
в цитатах больше не скрываются. Пропуск имеет `context_only`, в это число не входит.

Этот пост и пользовательский пример RT используются для разработки,
поэтому не подходят как независимая оценка качества новой версии.

## Как добавлять следующие приёмы

1. Сохранить конкретный пропуск или ложное срабатывание: URL, исходную версию
   заголовка/текста, SHA-256, точный фрагмент, предполагаемый приём и говорящего.
   Полные собранные тексты хранить в приватной/игнорируемой базе, а не добавлять
   весь корпус в публичный репозиторий.
2. Определить проверяемый признак и границу: почему фрагмент подозрителен,
   какие обычные сообщения имеют похожую форму, что потребует внешних данных.
   Согласие с политическим мнением и название СМИ не являются признаками.
3. Добавить формулировки/падежи в `media_strazh/rules.py`, при необходимости
   ограниченное требование к контексту в `analysis.py`. Для каждого нового правила
   нужны положительные и отрицательные примеры, кавычки, отрицания и точные
   Unicode-координаты. Историческое слово или просто «министр заявил» недостаточны.
4. Запустить `python3 -m unittest discover -s tests -v`; затем пересчитать
   локальную базу (`python3 -m media_strazh reanalyze --db /путь/к/базе`), собрать
   сайт и проверить `python3 tests/browser_manual_check.py --site _site`.
   Браузерная проверка сравнивает реальный Wasm с нативным Python, в том числе
   на контекстных примерах и длинных почти совпадающих конструкциях.
5. Отдельно измерить пропуски и лишние срабатывания на заранее отложенном,
   полностью размеченном корпусе. Корпус, использованный для настройки правил,
   не является таким тестом. Нынешний `evaluate` оценивает категории только
   для `needs_review`; качество цитат и точность границ нужно оценивать отдельно.
6. При выпуске повысить `VERSION`, обновить каталог/ограничения, пересчитать
   сохранённые тексты и собрать браузерный пакет. GitHub Pages получает общую
   версию после слияния PR и успешной сборки Actions. Изменение правил без новой
   версии оставило бы старые анализы в базе.

## Цитаты, вырванные из контекста

Знак пропуска — наблюдаемое редактирование. Цитата может быть искажена и без
него, а корректная цитата может содержать сокращение. По одному тексту
публикации факт искажения не устанавливается; эта категория остаётся
`not_evaluated` в текущем анализаторе.

Для следующего слоя проверки нужны исходное интервью/полная стенограмма,
дата и говорящий, вопрос интервьюера и соседние ответы. Затем можно сопоставить
цитату с оригиналом и выделить пропущенные отрицания, условия, адресата,
исправления и склейку удалённых частей. Несовпадение формулировок или отсутствие
стенограммы само по себе не доказывает искажение: бывают переводы и разные версии.
Подтверждённое соответствие должно храниться вместе с источником и координатами,
а смысловое решение — отдельно, с объяснением и возможностью ручной проверки.

Для поста Блахи первоисточник сейчас не установлен. Доступный текст позволяет
проверять риторические формулировки и увидеть `<...>`, но не восстановить удалённую
речь. Автоматический поиск интервью и семантическая сверка пока не реализованы.

Расширение исторических аналогий опирается на определения *Reductio ad hitlerum*,
*Name calling* и *Loaded language* в первичных руководствах SemEval/EMNLP,
перечисленных в [research.md](research.md). Аналогия бывает содержательной;
наши правила задают вопрос для проверки, а не объявляют её ошибкой по имени Гитлера.
