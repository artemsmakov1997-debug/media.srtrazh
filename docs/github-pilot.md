# Бесплатный пилот на GitHub Pages

Для публичного репозитория можно использовать стандартные бесплатные исполнители
GitHub Actions и GitHub Pages. Сервер, платная модель и ключи API не нужны.
Каждый запуск получает ограниченную подборку из RSS, загружает основной текст
доступных статей, анализирует его и собирает статический сайт.

Страница `analysis.html` показывает заголовки, ссылки на оригиналы, найденные
фрагменты, объяснения и состояние источников. Даты отображаются по Москве.
Можно выбрать источник и оставить публикации с фрагментами для проверки.
Найденные признаки не доказывают манипуляцию; рейтинг СМИ здесь не вычисляется.

## Анализ новости вручную

На `analysis.html` над автоматической подборкой находится форма
**Анализировать новость вручную**. Вставьте полный текст, при желании добавьте
заголовок и нажмите **Проанализировать**. Совместный предел — 200 000 символов.
Вместо поля ввода появляется тот же полный текст с подсвеченными фрагментами,
без повторной копии и списка карточек под формой. Наведите мышь или коснитесь
выделения, чтобы прочитать пояснение и статус. С клавиатуры выделения доступны
через Tab; Enter или пробел открывает комментарий, Escape закрывает его.
Повторное касание и нажатие вне комментария также закрывают подсказку.
При пересечении нескольких признаков доступны все их пояснения.
Кнопка **Редактировать** возвращает исходные заголовок и текст к вводу.
Результат с версией, всеми находками и ограничениями можно скачать кнопкой
**Скачать результат JSON**. Внизу остаются две обязательные строки об
ограничениях анализа; дополнительные сообщения о языке и пределе находок
показываются рядом с формой при необходимости.
Кнопка **Очистить** также отменяет выполняющийся анализ.

Форма работает на GitHub Pages без API и отдельного сервера. Используется
тот же исходный Python-код, что в CLI и прежнем API, а не второй набор правил.
Введённый текст остаётся в браузере: он не отправляется в GitHub Actions,
не сохраняется в общей подборке, cookies или localStorage.
Экспорт содержит полный введённый текст и создаётся только по нажатию кнопки.

Для первого анализа браузер загружает примерно 12 МБ файлов движка с вашего
сайта. На медленном соединении загрузка может занять время. Пока страница открыта,
движок используется повторно. Нужен современный браузер с JavaScript,
WebAssembly и Web Worker. Ручная форма работает и при недоступной автоматической
подборке; отсутствие файлов самого движка показывается отдельной ошибкой.

## Как включить публикацию

Эти действия выполняет владелец репозитория после проверки изменений:

1. Объедините pull request с бесплатным пилотом в `main`.
2. Откройте репозиторий → **Settings → Pages → Build and deployment**.
   В поле **Source** выберите **GitHub Actions** вместо **Deploy from a branch**.
   Существующий домен `media-strazh.ru` оставьте.
3. Откройте **Actions → Collect news and publish analysis → Run workflow**.
   Выберите ветку `main` и подтвердите запуск.
4. Дождитесь успешного завершения заданий **build** и **deploy**.
5. На странице рейтинга нажмите **Показать полный список**, затем кнопку
   **Анализ публикаций** внизу открывшегося окна. Страница находится по пути
   `/analysis.html`. Для просмотра свежей подборки обновите страницу.

Дальше расписание запускает сбор на 17-й и 47-й минутах каждого часа UTC,
то есть примерно раз в 30 минут. Изменения в ветке `main` также автоматически
запускают сбор и публикацию сайта. GitHub может задерживать или пропускать
запуски при нагрузке. В публичном репозитории расписание может отключиться
после 60 дней без активности. Этот пилот не гарантирует непрерывную работу 24/7.

Публикация разрешена только из `main`. Ручной запуск из другой ветки пропускает
только задание `deploy`: сбор, тесты и создание артефакта выполняются.
Запуски разных веток используют разные группы очереди. Старый workflow
`pages-build-deployment` относится к прежнему режиму
публикации сайта. Если **deploy** завершается ошибкой, проверьте выбранный режим
Pages и ограничения среды `github-pages` в настройках репозитория.

## Какие данные публикуются

Сайт содержит существующие HTML-страницы и изображения, новую страницу анализа
и `data/analysis.json`. В JSON входят заголовки, адреса, даты, ограниченные
фрагменты контекста, объяснения, версия алгоритма и состояние источников.
Для Telegram добавляются предпросмотр до 160 символов и отметка пересылки;
отдельного заголовка у сообщения нет.
Артефакт Pages публичного репозитория также может быть доступен пользователям GitHub.

Полный текст собранной статьи отдельным полем, исходный HTML, база SQLite,
серверные модули и выгрузки корпуса в сборку не включаются.
Для ручного анализа в `data/manual-engine.json` входят только три исходных
файла пакета: `__init__.py`, `analysis.py` и `rules.py`. Проверенный движок
Pyodide 0.29.3, его лицензия и уведомления размещаются в `vendor/pyodide/`.

В `main` накопленная SQLite-база восстанавливается из GitHub Actions cache,
а при отсутствии кэша создаётся новая. Обновлённая база сохраняется после
запуска. Кэш может истечь или быть удалён; он не заменяет резервную копию
постоянного архива. Проверки feature-веток используют собственную временную
базу и не записывают кэш основной истории.

Перед сбором выполняются `reextract --outdated-only` и `reanalyze`:
устаревшие тексты обновляются по сохранённому HTML, а ранее полученные статьи
пересчитываются текущими правилами. Неизменные проверенные тексты не обрабатываются
повторно. Первоначальный `extractor_version` и дата получения сохраняются;
отдельная таблица `extraction_checks` фиксирует проверку новой версией.
Никаких дополнительных запросов к сайтам эти команды не делают.

Цикл получает до двух полных текстов от каждой ленты. Реестр содержит 18 сайтов,
19 настроенных Telegram-каналов и один незаполненный слот «Ленты.ру», включая
«Аргументы и факты», «ИноСМИ», «СМОТРИ» и отдельно «Лентач».
Публичная подборка содержит до 100 публикаций. Материалы с находками имеют
приоритет перед нейтральными; места распределяются между лентами, затем
результат сортируется по дате. Страница показывает материалы с находками и
фильтрует их по выбранному маркеру — это поведение пользовательской версии.
В пределах 40 опубликованных находок сохраняется представительство разных
категорий, чтобы поздний редкий маркер не исчезал из фильтра.
Общая RSS-лента не гарантирует охват всех новостей и авторских колонок.
Кэш не предназначен для секретов или приватных пользовательских текстов;
он отделён от публичной сборки сайта, но доступ зависит от прав GitHub-репозитория.

Ошибка одного источника сохраняется в JSON и журнале и не мешает публикации
результатов других. В облачной проверке часть сайтов отказала в доступе
или запретила загрузку через `robots.txt`. Результаты проверки перечислены в
[реестре источников](sources.md). В исполнителях GitHub доступность может
отличаться. RSS-анонс не подменяет полный текст статьи.
Telegram собирается из открытых веб-лент каналов: сообщения с текстом или
подписью к медиа, без распознавания изображений, видео и аудио. Для неизвестного
адреса проверяются социальные ссылки официального сайта; неоднозначность или
отсутствие доступа показываются как ошибка сбора. См. [реестр источников](sources.md).
Цикл сбора ограничен 900 секундами: уже полученные результаты сохраняются,
а оставшиеся источники отмечаются как не проверенные в пределах бюджета.
Задание сборки ограничено 25 минутами; при затянувшейся загрузке предыдущий
успешно опубликованный сайт остаётся доступен. Расписание не гарантирует охват
каждого сообщения или получение недоступных материалов.

Если нет ни одной статьи с анализом текущей версии, сборка завершается ошибкой,
и новая версия сайта не публикуется. Предыдущая опубликованная подборка остаётся
доступна со своей датой обновления.

## Проверка в Codespaces или локально

Нужен Python 3.10+ без внешних зависимостей. Workflow использует Python 3.12.
Из корня репозитория:

```sh
python3 -m unittest discover -s tests -v
python3 -m media_strazh prepare-browser
python3 -m media_strazh collect --db /tmp/pilot.sqlite3 --limit 2 --time-budget-seconds 900 --verbose
python3 -m media_strazh build-site --db /tmp/pilot.sqlite3 --output _site --limit 100
python3 -m http.server 8002 --directory _site
```

В Codespaces откройте вкладку **Порты**, найдите порт **8002** и нажмите
**Открыть в браузере**. На главной странице нажмите **Показать полный список**,
затем **Анализ публикаций** внизу окна.
Остановить локальный сервер можно сочетанием Ctrl+C.

Если `collect` вернул код 1 из-за недоступного источника, сборку можно продолжить
при наличии статей остальных источников. Код 2 означает ошибку запуска:
её нужно исправить. Отсутствие анализов также приводит к коду 2 у `build-site`.
Папка `_site/` — результат сборки, `_runtime/` — кеш браузерного движка;
обе исключены из Git. `prepare-browser` получает закреплённую версию из
официального npm-реестра и проверяет SHA-512 архива. Сборка проверяет контрольные
суммы файлов и отказывается публиковать отсутствующий или повреждённый движок.

## Проверка браузерной формы

Unit-тесты используют маленькие локальные фикстуры и не требуют сети или браузера.
Для дополнительной проверки настоящего WebAssembly-движка подготовьте сайт,
установите инструменты проверки и выполните:

```sh
python3 -m pip install playwright==1.62.0
python3 -m playwright install chromium
python3 tests/browser_manual_check.py --site _site
```

Скрипт сравнивает результаты в браузере с Python на всех входных примерах
существующих тестов анализа и риторики, включая ошибки валидации, цитаты,
отрицания, Unicode и предел результатов. Он также проверяет форму, экспорт,
повторный запуск после ошибки загрузки и сетевые запросы без передачи введённого
текста. В Actions эти проверки выполняются при изменении `main` и ручном запуске;
запуски по расписанию обходятся без установки браузера.
