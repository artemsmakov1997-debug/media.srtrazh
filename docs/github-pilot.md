# Бесплатный пилот на GitHub Pages

Для публичного репозитория можно использовать стандартные бесплатные исполнители
GitHub Actions и GitHub Pages. Сервер, платная модель и ключи API не нужны.
Каждый запуск получает ограниченную подборку из RSS, загружает основной текст
доступных статей, анализирует его и собирает статический сайт.

Страница `analysis.html` показывает заголовки, ссылки на оригиналы, найденные
фрагменты, объяснения и состояние источников. Даты отображаются по Москве.
Можно выбрать источник и оставить публикации с фрагментами для проверки.
Найденные признаки не доказывают манипуляцию; рейтинг СМИ здесь не вычисляется.

## Как включить публикацию

Эти действия выполняет владелец репозитория после проверки изменений:

1. Объедините pull request с бесплатным пилотом в `main`.
2. Откройте репозиторий → **Settings → Pages → Build and deployment**.
   В поле **Source** выберите **GitHub Actions** вместо **Deploy from a branch**.
   Существующий домен `media-strazh.ru` оставьте.
3. Откройте **Actions → Collect news and publish analysis → Run workflow**.
   Выберите ветку `main` и подтвердите запуск.
4. Дождитесь успешного завершения заданий **build** и **deploy**.
5. На сайте нажмите **Анализ публикаций**. Страница находится по пути
   `/analysis.html`. Для просмотра свежей подборки обновите страницу.

Дальше расписание запускает сбор на 17-й и 47-й минутах каждого часа UTC,
то есть примерно раз в 30 минут. GitHub может задерживать или пропускать
запуски при нагрузке. В публичном репозитории расписание может отключиться
после 60 дней без активности. Этот пилот не гарантирует непрерывную работу 24/7.

Публикация разрешена только из `main`. Ручной запуск из другой ветки пропускает
задания. Старый workflow `pages-build-deployment` относится к прежнему режиму
публикации сайта. Если **deploy** завершается ошибкой, проверьте выбранный режим
Pages и ограничения среды `github-pages` в настройках репозитория.

## Какие данные публикуются

Сайт содержит существующие HTML-страницы и изображения, новую страницу анализа
и `data/analysis.json`. В JSON входят заголовки, адреса, даты, ограниченные
фрагменты контекста, объяснения, версия алгоритма и состояние источников.
Артефакт Pages публичного репозитория также может быть доступен пользователям GitHub.

Полный текст статьи отдельным полем, исходный HTML, база SQLite, Python-модули
и выгрузки корпуса в сборку не включаются.

Каждый запуск использует новую временную базу и получает до пяти полных статей
от каждого источника. Ранее опубликованная подборка заменяется свежей.
История статей между запусками не накапливается. Общая RSS-лента не гарантирует
охват всех новостей; отдельные авторские колонки могут в неё не попасть.
Для постоянного архива и очереди загрузки понадобится следующий этап.

Ошибка одного источника отображается на странице и не мешает публикации
результатов других. В облачной среде RT и РИА доступны; ТАСС отдаёт RSS,
но основной текст и `robots.txt` отвечают HTTP 403. В исполнителях GitHub
доступность может отличаться. RSS-анонс не подменяет полный текст статьи.

Если нет ни одной статьи с анализом текущей версии, сборка завершается ошибкой,
и новая версия сайта не публикуется. Предыдущая опубликованная подборка остаётся
доступна со своей датой обновления.

## Проверка в Codespaces или локально

Нужен Python 3.10+ без внешних зависимостей. Workflow использует Python 3.12.
Из корня репозитория:

```sh
python3 -m unittest discover -s tests -v
python3 -m media_strazh collect --db /tmp/pilot.sqlite3 --limit 5 --verbose
python3 -m media_strazh build-site --db /tmp/pilot.sqlite3 --output _site --limit 30
python3 -m http.server 8002 --directory _site
```

В Codespaces откройте вкладку **Порты**, найдите порт **8002** и нажмите
**Открыть в браузере**. На главной странице выберите **Анализ публикаций**.
Остановить локальный сервер можно сочетанием Ctrl+C.

Если `collect` вернул код 1 из-за недоступного источника, сборку можно продолжить
при наличии статей остальных источников. Код 2 означает ошибку запуска:
её нужно исправить. Отсутствие анализов также приводит к коду 2 у `build-site`.
Папка `_site/` — результат сборки; она исключена из Git.
