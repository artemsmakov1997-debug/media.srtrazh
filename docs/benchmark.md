# Проверочный корпус и разметка

Корпус первого пилота — 240 реальных публикаций, выбранных из накопленной
истории: 160 для разработки, 80 отложенных. Отложенную часть не используют
для настройки правил. Проверяющий первого пилота — владелец проекта.
Разметка изначально отсутствует: `fully_annotated=false`, `labels=null`,
`spans=[]`. Предсказания анализатора не подставляются вместо человеческих меток.

## Как получить пакет

В GitHub откройте **Actions → Collect news and publish analysis**. Укажите
ветку с этими изменениями в **Run workflow**, включите параметр **benchmark**.
Запуск восстанавливает историю только для чтения из Actions cache и обрабатывает
её в отдельной машине. Он не сохраняет cache поверх основной истории и не
публикует Pages, в том числе при запуске на `main`.

После завершения в разделе **Artifacts** находится `review-corpus-НОМЕР_ЗАПУСКА`.
Скачайте и распакуйте архив. В нём:

- `review-corpus/annotation.html` — локальная форма;
- `development.jsonl`, `holdout.jsonl` — полные тексты без предсказаний;
- `manifest.json` — фиксированные id, хеши оригиналов и разделение;
- `annotation-status.json` — готовность разметки, первоначально без метрик;
- `quality-report/before.json`, `after.json` — аудит сбора и дат до/после извлечения.

Артефакт хранится 30 дней. Сохраните пакет у себя целиком, включая манифест:
Actions cache и артефакты не являются постоянным архивом. Если в cache уже нет
достаточного корпуса, команда завершится ошибкой, а не создаст вымышленные статьи.
Для повторного измерения используйте сохранённый пакет, а не заново выбранную
выборку из изменившейся базы.

## Работа проверяющего

1. Откройте `annotation.html` в браузере. Сервер не нужен. Выберите
   `development.jsonl` и укажите своё имя или постоянный псевдоним проверяющего.
2. Прочитайте весь текст. Источник по умолчанию скрыт, его можно показать,
   если для понимания нужен оригинал. Форма не показывает предсказания алгоритма.
3. Выделите точные слова в заголовке или тексте. Выберите приём и голос,
   нажмите «Добавить выделенное». Один фрагмент может иметь несколько категорий.
4. Проверьте весь материал по всем десяти категориям, поставьте отметку
   завершения и нажмите «Документ проверен». Без признаков список остаётся
   пустым; только после явного подтверждения он становится отрицательным примером.
5. Регулярно нажимайте «Скачать разметку JSONL». Браузер сохраняет прогресс
   локально, но скачанный файл нужен для переноса и резервной копии. Для продолжения
   можно открыть исходный файл в том же браузере или выгруженный JSONL на другом.
6. Спорный фрагмент отметьте «Не уверен», поясните причину в заметке.
   Такой документ не участвует в метриках до решения. Для исправления завершённой
   разметки используйте «Вернуть к проверке».

После согласования инструкции разумно начать с 10–20 документов. Затем
проверить, не расходится ли понимание категорий, и закончить первую часть.
Отложенные 80 размечают после фиксации оцениваемой версии. Исправление правил
по их результатам превращает эту часть в материал разработки: для следующей
независимой проверки понадобится новый отложенный набор.

Оригинал не редактируется; координаты считаются в Unicode code points.
Форма не отправляет тексты, заметки и имя проверяющего по сети. Переход по
исходной ссылке — обычное открытие сайта самим пользователем.

## Что считать признаком

Размечается наблюдаемый риторический приём, требующий проверки, а не политическая
позиция, установленная ложь или намерение автора. Оценка или метафора сама
по себе не всегда служит манипулятивной подаче: учитывайте её функцию в контексте.
Сомнение лучше зафиксировать отдельно, чем назначить метку по одному слову.

Голос отмечается отдельно:

- **Авторское утверждение** — редакционный рассказ или комментарий без явного
  дистанцирования от формулировки.
- **Цитата/переданная речь** — слова другого говорящего, в том числе пересказ
  с явной атрибуцией; цитирование не доказывает одобрение редакции.
- **Отрицание/обсуждение** — формулировка приведена как отвергнутый тезис или
  предмет языкового разбора. «Не меньше» само по себе не отрицает эпитет.
- **Не уверен** — адресат, смысл или говорящий не установлены по этому тексту.

Названия и определения десяти категорий — в [algorithm.md](algorithm.md).
«Силовик» и информационные обозначения события сами по себе не входят в эти
риторические метки. Проверка вырванной из контекста цитаты и псевдостатистики
требует внешних материалов; они не оцениваются нынешними десятью категориями.
Отсутствие меток не означает нейтральность или истинность публикации.

## Как выбирается выборка

Отбор использует источник и длину текста, затем воспроизводимый хеш с seed.
Срабатывания/несрабатывания правил и название политической позиции в отборе
не участвуют. Учитываются текущие версии сохранённых текстов; наличие даты не
требуется для проверки риторики. Известные публикации из прежних пользовательских
примеров исключаются по URL. Это не исчерпывающий реестр всех когда-либо
прочитанных разработчиком материалов.

Удаляются повторные канонические ссылки и одинаковые нормализованные тексты.
Для похожих текстов используется эвристика общих минимальных пятисловных
шинглов и Jaccard ≥ 0,85. Она не гарантирует устранение всех пересказов,
укороченных репостов и материалов об одном инфоповоде. В итоговую выборку входит
один представитель найденного дубля, поэтому он не попадает в обе части.
Список и хеши фиксируются манифестом. Это диагностический сбалансированный набор,
а не репрезентативная оценка доли манипуляций по всему медиарынку.

## Подготовка и оценка командами

```sh
python3 -m media_strazh prepare-benchmark --db /путь/к/копии.sqlite3 --output exports/review-pilot --size 240 --seed pilot-2026-1
python3 -m media_strazh evaluate-benchmark --file exports/review-pilot/reviewed-development.jsonl --manifest exports/review-pilot/manifest.json --split development
```

Команда не перезаписывает существующий каталог и отказывает при недостаточной
выборке после исключений. Исходный манифест при оценке обязателен: id, часть
корпуса и SHA-256 должны соответствовать оригиналу. Изменённый текст, некорректные
границы, дубли, неподдержанные категории и разметка без проверяющего отвергаются.

Пока нет подтверждённых меток, результат — `awaiting_human_review`, `metrics=null`.
Частичная проверка показывает непроверенные и спорные документы. Пропущенные
из манифеста документы не считаются отрицательными или проверенными.

После проверки считаются:

- precision/recall/F1 категорий авторской речи на уровне документа;
- точные границы и совпадения с IoU ≥ 0,5, с учётом категории и голоса;
- показатели по категориям и статусам;
- правильность голоса на сопоставленных фрагментах;
- список расхождений с rule_id для разбора ошибок, до 200 документов.

Сопоставление фрагментов — жадное по наибольшему IoU, один к одному; при
пересечениях оно может отличаться от глобально оптимального сопоставления.
Порог 0,5 — инженерный критерий, а не доказанная универсальная норма.
Неопределённые доли возвращаются как `null`, а не как нулевая точность.
Один проверяющий не позволяет измерить согласие разметчиков и не устанавливает
объективную истинность меток. Текущие программные тесты используют синтетические
примеры отдельно от этого настоящего, первоначально неразмеченного корпуса.
